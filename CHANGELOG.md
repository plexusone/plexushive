## [v0.3.0] - 2026-11-19

### Highlights

- Operator actions: pushes, merges, tags, deploys and setup steps with the exact command, listed first in the briefing
- Work in progress by repository and branch, with `plexushive who` to see who is working in a repository before changing it
- `plexushive decide` answers a decision request and writes the decision the role reads

### Added

- `operatorActions` in reports: kind, command, repository, branch, commit, pull request, version, checks, whether it is irreversible and what it unblocks ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- `inProgress` in reports: repository, branch, worktree and base of work under way ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- `notices`, `session` and `idle` in reports ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- Items carry branch, commits, pull requests, state and paths; blockers name the decision request that unblocks them and what they hold up; options can be marked irreversible; decision requests keep when they were first asked ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- `DecisionRequest.Decide` and `WriteDecision`, which never replaces an existing decision ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- `decide` and `who` commands and a `--version` flag ([`860dadd`](https://github.com/plexusone/plexushive/commit/860dadd))

### Changed

- The briefing lists operator actions first, keys decisions as `role/id`, separates answered requests, groups work in progress by repository and flags shared repositories, and ignores reports from unknown or retired roles ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- `NewBriefing` takes the decision log as a second argument ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))
- `report submit` keeps when each decision request was first asked ([`860dadd`](https://github.com/plexusone/plexushive/commit/860dadd))

### Fixed

- Decided titles read "<question> Decided: <option>", and `who` does not pad role lines without a session ([`7985bf5`](https://github.com/plexusone/plexushive/commit/7985bf5))

### Documentation

- Operator actions, work in progress, `decide` and `who` in the README, user guide, CLI reference and status report reference ([`9960047`](https://github.com/plexusone/plexushive/commit/9960047))
- v0.3.0 release notes

### Tests

- Tests for the new report fields, briefing sections, decisions from requests and the new commands ([`bb379ca`](https://github.com/plexusone/plexushive/commit/bb379ca))

## [v0.2.0] - 2026-11-19

### Highlights

- Status reports: each role files what it finished, what is blocked and on whom, what it does next, and the decisions it needs
- `plexushive brief` gathers every report into one briefing: decisions first, then blockers, then each role's status and who has not reported

### Added

- `Report`, `Item`, `Blocker`, `DecisionRequest` and `Option` types with validation; a decision request's recommendation must name one of at least two options ([`a34d45d`](https://github.com/plexusone/plexushive/commit/a34d45d))
- `ValidateReports` checks reports against the roles: one per role, no retired roles, and blockers that wait on a role or the operator ([`a34d45d`](https://github.com/plexusone/plexushive/commit/a34d45d))
- JSON Schema for status reports ([`a34d45d`](https://github.com/plexusone/plexushive/commit/a34d45d))
- `WriteReport`, `LoadReports` and `ReportsDir`: one atomically replaced report per role in `$HIVE_REPORTS` or the per-user data directory ([`798d047`](https://github.com/plexusone/plexushive/commit/798d047))
- `NewBriefing` gathers reports into decisions, blockers, status and missing roles ([`66b192e`](https://github.com/plexusone/plexushive/commit/66b192e))
- `report submit` command, filling the role from `HIVE_ROLE` and the time from the clock, and `brief` command with `--json` output ([`92ea167`](https://github.com/plexusone/plexushive/commit/92ea167))

### Changed

- The role name `operator` is reserved for blockers that wait on the operator ([`a34d45d`](https://github.com/plexusone/plexushive/commit/a34d45d))

### Documentation

- Status reports in the README, user guide, CLI reference and a new reference page ([`e6d2fb8`](https://github.com/plexusone/plexushive/commit/e6d2fb8))
- v0.2.0 release notes

### Tests

- Tests for reports, the report store, briefings and the new commands, kept out of the real per-user data directory ([`ff11ba2`](https://github.com/plexusone/plexushive/commit/ff11ba2))

## [v0.1.0] - 2026-11-19

### Highlights

- Roles, decisions and a message envelope as JSON for coordinating long-lived coding agents, with Go types as the source of truth
- Repository stewardship: several roles may work in a repository, at most one stewards it, and organization patterns are supported
- `plexushive` CLI to validate a hive directory, list the roles working in a repository and print the JSON Schemas

### Added

- `Role` format with status, mission, autonomy (`observe`, `prepare`, `execute`), repository affinities, initiatives and peers ([`6d74225`](https://github.com/plexusone/plexushive/commit/6d74225))
- `Decision` format for an append-only decision log, with alternatives and supersede links validated in both directions ([`6d74225`](https://github.com/plexusone/plexushive/commit/6d74225))
- Message `Envelope` with `Format` and `Parse` for `question`, `request`, `status` and `decision-needed` messages ([`6d74225`](https://github.com/plexusone/plexushive/commit/6d74225))
- `RolesFor` and `Steward` resolve the roles that work in a repository, steward first ([`6d74225`](https://github.com/plexusone/plexushive/commit/6d74225))
- `Load` reads a hive directory strictly, and `Hive.Validate` checks roles and decisions together ([`3ad0eda`](https://github.com/plexusone/plexushive/commit/3ad0eda))
- JSON Schemas for roles and decisions generated from the Go types ([`3ad0eda`](https://github.com/plexusone/plexushive/commit/3ad0eda))
- `plexushive validate`, `roles` and `schema` commands ([`2bdc377`](https://github.com/plexusone/plexushive/commit/2bdc377))

### Documentation

- README covering roles, stewardship, decisions and the envelope ([`933c603`](https://github.com/plexusone/plexushive/commit/933c603))
- User guide covering roles, sessions, decisions, validation and messages ([`1cbd3bc`](https://github.com/plexusone/plexushive/commit/1cbd3bc))
- Documentation site with installation, quick start, user guide and reference for roles, decisions, messages, the CLI and the JSON Schemas ([`4c3c96d`](https://github.com/plexusone/plexushive/commit/4c3c96d))
- v0.1.0 release notes

### Build

- CI, lint and CodeQL workflows ([`1c58ec4`](https://github.com/plexusone/plexushive/commit/1c58ec4))

### Tests

- Unit tests for validation, routing, loading, the envelope and the CLI against an example hive ([`ba0178b`](https://github.com/plexusone/plexushive/commit/ba0178b))
- Schema tests compare regardless of line endings, so they pass on Windows ([`d13b4c7`](https://github.com/plexusone/plexushive/commit/d13b4c7))
