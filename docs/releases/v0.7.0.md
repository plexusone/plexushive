# Release Notes - v0.7.0

**Release Date:** 2026-11-22

## Overview

Most answers to decision requests are point decisions that unblock work:
land a branch now, link a runbook, patch-release a module. Their lasting
record is the result, such as a commit, a changelog entry or an ADR, and
writing each one to the decision log buried the working rules the log is
for. This release records answers on open items instead, and writes a
decision only when asked.

**Changed behavior:** `plexushive decide` no longer writes
`decisions/<id>.json` unless given `--record`.

## Changed

- `decide` records the answer (option, reason, date) on the request's open
  item, adding the item if it is not listed yet, and tells the work
  identity to act on it and record the outcome where it belongs
- `decide --record` also writes the answer to the decision log, for
  working rules that bind the agents
- A design record's question is `answered`, not decided, until its work
  identity has written the answer into the document; the message says
  which document, and `open sync` decides the item once the request leaves
  the report

## New Features

- A new open item status, `answered`, and an `answer` field on items
- `brief` lists answered requests with the chosen option, and ends with a
  count of open items still needing something, including design questions
  no report carries
- `context` shows the answers to the session's requests with their reasons
- `open` shows each item's answer; answered items are listed after the open
  ones

## Library

- `hive.Answer`, `hive.ItemAnswered` and `OpenItem.Answer`
- `(*OpenItems).Record` records an answer; `(*Hive).Answered` reports
  whether a work identity's request is answered, on an open item or in the
  decision log
- `hive.NewHiveBriefing` builds a briefing that uses open items' answers;
  `hive.NewBriefing` still uses the decision log alone
- `IdentityDecision.Option` and `Context.Answers`

## Installation

```bash
go install github.com/plexusone/plexushive/cmd/plexushive@v0.7.0
```
