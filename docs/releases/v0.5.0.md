# Release Notes - v0.5.0

**Release Date:** 2026-11-22

## Overview

A hive record says what one long-lived agent is for and where it works.
That is a **work identity**: a line of work, with a purpose and an address,
that sessions take on. Until now plexushive called it a role, but role
already has a settled meaning in access control, a permission level such as
`admin` or `viewer` that a principal holds, and agents and people hold both
kinds of record side by side. This release renames roles to work
identities and leaves role to mean an access level.

**Breaking changes for Go callers and JSON readers:** the types, functions,
directories, environment variable, flags and JSON fields are renamed (see
below). Records, reports, sessions and scripts written for v0.4 keep
working: reading accepts every old name, and writing uses only the new
ones, so a hive can move over one session at a time.

## Changed

| Before | Now |
|---|---|
| `roles/<name>.json` | `identities/<name>.json`; a hive with both directories is refused |
| `HIVE_ROLE` | `HIVE_IDENTITY`, read first in the environment and in tmux |
| `--role` | `--identity`; `--role` still works and is deprecated |
| `plexushive roles <repo>` | `plexushive identities <repo>`; `roles` is an alias |
| `plexushive start <role>` | `plexushive start <identity>` |
| `"role"` in a report | `"identity"` |
| `"roles"` in a decision | `"identities"` |
| `role`, `roles` in briefing and context JSON | `identity`, `identities` |
| `contributor` affinity | `collaborator`, so it is not confused with a contributor access role |
| `plexushive schema role`, `role.schema.json` | `plexushive schema identity`, `identity.schema.json` |

`plexushive whoami` says when it found the identity under `HIVE_ROLE`; run
`plexushive start <identity>` again to bind the new variable.

## Moving a hive

1. Install v0.5.0 for every session on the machine first; earlier versions
   cannot read the new names.
2. `git mv roles identities` in the hive directory, and replace
   `"contributor"` with `"collaborator"` in the records when convenient.
3. Rebind each session with `plexushive start <identity>`. Reports and
   decisions move to the new field names the next time they are written.

## New Features

- `plexushive report show [identity]` prints a work identity's stored
  report as JSON, to edit and submit again

## Library

- `hive.WorkIdentity`, `hive.IdentityStatus`, `hive.IdentityDraft`,
  `hive.IdentityActive`, `hive.IdentityRetired`
- `hive.IdentitiesFor`, `hive.LoadIdentities`, `hive.ValidateIdentities`,
  `hive.IdentitySchema`, `hive.IdentitiesDir` and `hive.LegacyIdentitiesDir`
- `hive.IdentityEnv` and `hive.LegacyIdentityEnv`; `hive.ResolveIdentity`,
  `hive.BindTmuxIdentity`, `hive.TmuxIdentity`, and the `IdentitySource`
  values `SourceLegacyEnv` and `SourceLegacyTmux` with `Legacy()`
- `Hive.Identities`, `Hive.Identity`, `Report.Identity`,
  `Decision.Identities`, `Context.Identity`, `Peer.Identity`,
  `Match.Identity`, `UnreadableReport.Identity`
- `hive.IdentityAction`, `IdentityDecision`, `IdentityBlocker`,
  `IdentityWork` and `IdentityNotice`, with `Identity` and `Identities`
  fields
- `hive.AffinityCollaborator`
