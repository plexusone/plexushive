# Release Notes - v0.3.0

**Release Date:** 2026-11-19

## Overview

This release puts the operator's work first. Under a rule that only the
operator pushes and tags, most finished work ends in a step only the
operator can take, and that step used to be filed as a blocker. Reports
now list those steps as operator actions with the exact command, say which
repository and branch each role is working in, and close the loop on
decisions: `plexushive decide` answers a request and writes the decision
the role reads.

**Breaking changes:** `hive.NewBriefing` takes the decision log as a second
argument, and its JSON gains fields. Existing reports stay valid.

## New Features

### Operator actions

```json
"operatorActions": [{
  "kind": "tag",
  "description": "Tag the coupon release.",
  "command": "git -C billing tag v1.4.0 && git -C billing push origin v1.4.0",
  "repository": "github.com/example/billing",
  "checks": ["https://github.com/example/billing/actions/runs/1"],
  "irreversible": true
}]
```

Kinds are push, merge, tag, deploy, create-repository, configure, test,
review and other. The briefing lists actions first, grouped by kind, and
marks irreversible ones.

### Work in progress

`inProgress` lists the repository, branch, worktree and base of each piece
of work under way. The briefing groups it by repository and flags
repositories with more than one role. `plexushive who
github.com/<org>/<repo>` shows a repository's steward and contributors with
how to reach their sessions, the work in progress there and the actions
waiting on it.

### Decision answers

`plexushive decide <role>/<id> <option>` turns a decision request into a
decision under the same ID, with the other options as alternatives, and
prints the message to send the role. It never replaces an existing
decision. The briefing keys requests as `role/id`, shows how long each has
waited, and lists requests the log already answers until the role drops
them.

### Richer reports

- Items carry `branch`, `commits`, `pullRequests`, `state` (committed,
  pushed, released, deployed) and `paths`
- Blockers name the decision request that unblocks them and what they hold
  up
- Options can be marked irreversible
- `notices` tell other roles about something that affects them, such as a
  bug in a shared dependency
- `session` says how to reach the session playing the role, and `idle`
  says the role has nothing to do
- The briefing ignores reports from unknown or retired roles and lists them
